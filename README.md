# Из съёмки в CAD

Контекст проекта **photogrammetry-to-cad**: как по фотографиям или видео реального объекта получить понятную редактируемую инженерную модель, используя готовые инструменты под управлением агента.

Первый пример — секция уличной беседки. Идея возникла из задачи мягких окон, но проект шире: мы проверяем перенос измеренной геометрии в CAD. Проектирование и раскрой окон сейчас в задачу не входят.

## Где мы находимся

**На 20 ноября 2026 года выбран маршрут первого эксперимента. Сквозной запуск на собственной съёмке ещё не подтверждён.** В репозитории пока документация и шаблоны, а не работающий runtime или сервис.

Договорились сохранить KISS: использовать штатные функции, CLI и предусмотренные расширения; не менять ядра инструментов. Локальное отсутствие CUDA больше не ограничивает выбор: GPU планируется арендовать на Vast.ai.

**Рабочая цепочка:**

> Видео или фотографии → Meshroom + AliceVision → плотное облако → CloudCompare → параметры элементов с проверкой неоднозначностей → build123d → CAD-модель.

Главная ещё не проверенная часть — переход **от найденных поверхностей к границам и параметрам отдельных деталей**. Обнаружение плоскостей само по себе не решает эту задачу. Для первого прохода допустимо подтверждение человеком; его объём нужно записывать.

## Что считаем полезным результатом

Пользователь открывает модель собственной конструкции, видит отдельные элементы, меняет их параметры и получает STEP, который открывается в CAD. Отдельно видны ошибки относительно контрольных замеров и участки, восстановленные по предположению.

Красивое облако, успешный запуск GPU или файл STEP без проверки геометрии не доказывают выполнение этой задачи. Допустимые ошибки размеров ещё предстоит определить; заранее обещанной миллиметровой точности нет.

## Ближайший шаг

Подготовить **один сквозной запуск** по [плану эксперимента](docs/first-experiment.md): согласовать небольшой объект и необходимые размеры, собрать съёмку, проверить окружение на одной GPU-ноде, пройти до CAD и записать результат. Регистрация Vast.ai и баланс — на стороне владельца; подготовка воспроизводимого окружения и обработка — работа агента.

Доступ к облаку, готовность существующего VPS, материалы съёмки и бюджет запуска пока не подтверждены. Это не препятствует подготовке окружения и инструкций, но не даёт основания создавать оплачиваемую ноду прямо сейчас.

## Как поддерживать этот репозиторий

Текущие договорённости живут в `docs/`. Исторические материалы — в `research/archive/`; они не переопределяют выбранный маршрут. После реального запуска обновляем статус и ссылки на результаты. Новую зависимость добавляем, когда понятна конкретная проблема, которую она решает.

В Git храним документацию, рецепты запуска, небольшие параметры и обезличенные отчёты. Видео, фото, облака, вычислительный кэш, ключи и адреса частной инфраструктуры хранятся отдельно; порядок описан в [инфраструктуре](docs/infrastructure.md).
