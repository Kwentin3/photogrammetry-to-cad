# Рабочий цикл фотограмметрии — Goal #15

Дата: 24 ноября 2026. Статус: **проверки в работе**, итоговая приёмка ещё не выдана.
Источник и обязательный объём — [Goal #15](../../goal-15.md).

## Что получает пользователь

Один [короткий вход для агента](../../../.agents/skills/photogrammetry-workflow/SKILL.md)
ведёт от подготовки оператора через выбор режима к реальным cloud/mesh, просмотру
и решению по наблюдаемому дефекту. Человеку передаётся отдельная
[памятка](../../operator.md); технические команды остаются в capture/modes/runbook.

## База, источники и решения

База — `1829cd4dcab682d42585f89d26e08704d6c82413`, принятый head открытого
PR #14. По состоянию на начало работы main ещё не включает исправление union.
Новая ветка не требует предварительного merge и сохраняет эти исправления.

Перед изменениями сверены pinned native descriptors
[KeyframeSelection](https://github.com/alicevision/AliceVision/blob/d012d05589b528dcf57a2a0c805c0a5709df8613/meshroom/aliceVision/KeyframeSelection.py),
[FeatureExtraction](https://github.com/alicevision/AliceVision/blob/d012d05589b528dcf57a2a0c805c0a5709df8613/meshroom/aliceVision/FeatureExtraction.py)
и [PrepareDenseScene](https://github.com/alicevision/AliceVision/blob/d012d05589b528dcf57a2a0c805c0a5709df8613/meshroom/aliceVision/PrepareDenseScene.py).
Smart использует штатный KeyframeSelection; маски до признаков и плотные маски
имеют разных потребителей. Новый отборщик, оркестратор и детектор не нужны.
Первоначальные URL без подкаталога `aliceVision` вернули 404; проверены точные
пути из pinned source. Успех API не выдаётся за compute этих режимов.

Карта дополнена наблюдаемым выходом и следующим действием при неудаче;
capture — пробными кадрами и связью меток с объектом при масках/движении.
В runbook устранено устаревшее утверждение о непроверенном masked Standard:
реальный Standard dense-only подтверждён #12, другие сочетания явно отделены.

## Печатный комплект и реальная итерация

Созданы [PDF CCTag3](../../../templates/capture-kit/cctag3-print.pdf),
[manifest](../../../templates/capture-kit/manifest.json) и
[форма замеров](../../../templates/capture-kit/measurements.csv). Все четыре
страницы открыты: ID 0–3, центры, кольца 100 мм и две контрольные линии печати
по 100 мм. Native проверка растров конечного PDF пока не завершена.

На реальном cloud #12 выполнена штатная Open3D SOR-итерация. Кандидат
46130 → 44759 точек отклонён после просмотра: вместе с выступами исчезает часть
настоящей боковины. Исходные cloud/mesh и камеры сохранены.
[Отчёт с двумя сопоставимыми видами](geometry-iteration.md),
[повторяемый просмотр](../../geometry-review.md). Коррекция подписи viewer
сохраняет координатные единицы источника, не назначает всем входам unknown scale.
Новая съёмка и замеры владельца пока не выполнялись. Архивные данные #12 не
являются материалом, снятым по новой памятке; их физический масштаб неизвестен.

## Ограничение Windows и выбранная проверка PDF

Две попытки штатного Windows CCTag были остановлены общим Job-лимитом 2 GiB,
очистка деревьев подтверждена. В библиотеке выделяются большие фиксированные
массивы; уменьшение растров не решает этот предел. Policy, WSL и ядра не менялись.
Для обязательной native проверки готовится узкий CI в этом же репозитории:
Ubuntu 24.04, контейнер CPU 2 / RAM 4 GiB / 64 процессов, job 10 минут,
детектор 180 секунд. На входе только конечный PDF и публичный официальный runtime.
[GitHub](https://docs.github.com/en/billing/concepts/product-billing/github-actions)
указывает бесплатные стандартные runners в публичных репозиториях; artifact/cache
storage не создаётся. Платная аренда и чужие домашние среды не используются.
