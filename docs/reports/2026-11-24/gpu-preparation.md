**Реальный cloud → GPU маршрут и native обработка ещё не проверены.**

## Что уже проверено

- Принятый архив Meshroom: 600156630 B, SHA256
  `4ca3cfb0898b8000def4e68d513468a199b948329b63cdb6b257e427d295163b`.
  Повторное потоковое чтение прошло, 12486 записей. Архив не изменён.
- Обе COPYING совпадают с точными Meshroom/AliceVision commits из runtime lock.
  Собственных фото, cache и private config по inventory нет. Python test/certdata
  содержит штатные ключевые fixture; это не credentials владельца. Проверка не
  является полным поиском секретов во всех бинарниках.
- Фактические FFmpeg `libavutil.so.60.26.100`, `libavformat.so.62.12.100`,
  `libavcodec.so.62.28.100` включают `--disable-gpl --enable-nonfree` и
  `nonfree and unredistributable`. Поэтому публичный mirror текущего архива
  не подготовлен. [FFmpeg checklist](https://ffmpeg.org/legal.html),
  [configure licensing flags](https://github.com/FFmpeg/FFmpeg/blob/master/configure#L90-L95).
- Репозиторий технически допускает release assets этого размера; native API
  показал `immutable-releases.enabled=false`. Версионный тег не объявляется
  неизменяемым. Настройка репозитория не менялась.
- Native GitHub API + HTTP HEAD на публичном тестовом asset вернули 302 на
  `release-assets.githubusercontent.com` без скачивания бинарника. Это репетиция
  механизма получения ссылки, **не проверка ещё не созданного закрытого источника**.
- Подготовлены неизменённый MOV 16930901 B и три сохранённых JPEG 1399438 B,
  всего 18330339 B. Фото — отдельный входной набор из кадров прежнего реального
  видео, а не новая операторская съёмка. SHA исходного видео сохранён.
- Отдельно подготовлены 64 MiB и 29 B для проверки native rclone. Их объём
  не смешивается с объёмом съёмки.
- 78 локальных unittest, результат OK, два пропуска; Bash syntax исполняемого
  runtime-блока и 11 PowerShell-блоков runbook, UTF-8, локальные ссылки и
  `git diff --check` проверены. Reader lock допускает явный URL override при
  пустом основном URL. Эти проверки не заменяют реальную native приёмку на Linux.

## Локальная проверка HTTP: прерывание и повтор

Native aria2 **1.37.0 Windows x64** выполняла прямые команды с тем же
`configs/runtime-download.aria2.conf`, SHA256 конфигурации
`0c48e7c29545adf5e7e0ea91f1eb0b7513ecf79e7c70ea2493e1e8f2f1f10931`.
Источник — локальный HTTP-сервер с Range и сохранением фактических запросов;
файл 67108864 B, SHA256
`281e519df3077b557c6b03f5da83c4e8d397219259615dd7c3308f89cae8f2a6`.
Выбраны native 8 streams / min-split 16M; на этом размере начались четыре
одновременных запроса, а не восемь. Это проверка поведения, не сетевой benchmark.

| Фаза | Наблюдение |
|---|---|
| Прерывание | Native `--stop=3`, ограничение 4M, exit 7, 4.172 с; сохранён `.aria2` 126 B и ненулевые данные. Logical size 52559872 B не выдавался за объём принятых данных. |
| Продолжение | Exit 0, 1.484 с; сервер вернул 206 на Range с началами 2277376, 19021824, 35799040, 52559872. Итоговый whole-file SHA совпал; `.aria2` удалён штатно. |
| Готовый файл | Exit 0, 1.141 с; native log подтвердил существующую загрузку и успешный checksum, результат 0B/s. Один GET успел записать 131072 B в socket buffer сервера; полного повторного скачивания 64 MiB не было. |
| Недоступный источник | HTTP 404, native exit 3, 0.031 с, payload 0. Linux-цепочка `remote_job` → bootstrap здесь не запускалась. |

Сервер shutdown/join и завершение managed дерева подтверждены. Созданные download
файлы удалены, исходный fixture сохранён; raw logs/requests/commands/receipt
остались в приватной папке `issue-19/http-native-proof` вне Git. Первоначальный
критерий нулевого server payload для готового файла оказался неверным: сохранены
и 128 KiB буферной передачи, и факт native reuse. Результат не скрывает этот трафик.
Это не проверяет TLS/private GitHub source, Linux bootstrap, SFTP или GPU.

## Путь без новой платформы

Конфигурация владеет identity сборки; native aria2 получает архив, существующий
bootstrap проверяет/устанавливает его. Native rclone передаёт входы, а прежние
video_frames/reconstruction обрабатывают их. Нового downloader, transfer API,
оркестратора и патчей ядра нет. Подробности и порядок настройки — в [runbook](../../runbook.md).

Предложен закрытый Release владельца для его личных запусков. Постоянный locator
и временная signed-ссылка остаются вне Git. Account token используется только
на управляющей машине. Владелец разрешил создание источника и одну GPU-проверку
в пределах $0.60/ч, 1 часа и $1 суммарно; stop через 45 минут. Публикация и
реальная приёмка выполняются; результаты ниже остаются локальными до GPU-проверки.

## Неизмеренное и следующая проверка

Нет фактического времени загрузки образа, HTTP-доставки/проверки/распаковки ПО,
передачи задания и готовности новой ноды. Нет результатов повторного aria2
на GPU, bootstrap reuse, rclone skip/прерванного файла или нового native video/photo run.
Заявленные сетевые параметры оффера не заполняют эти пробелы.

План — одна нода, MOV → native отбор кадров и отдельный фото-набор → native
CameraInit/FeatureExtraction, без SfM/dense/CAD. Отдельный транспортный probe
включает большой файл выше cutoff, прерывание, завершение участников и повтор.
После backup и проверки результатов — destroy, отсутствие своего ID и ledger.

При штатной облачной доставке из локального канала исключается **600156630 B ПО**.
Это объём неизменённого архива, не измеренное ускорение. Старый baseline 519735401 B
не нужен свежему запуску, но остаётся необходимым для тех продолжений, которые
используют его камеры/cache. Его пропуск не выдаётся за ускорение передачи тех же
входов; сохранённые полезные результаты не удаляются.
