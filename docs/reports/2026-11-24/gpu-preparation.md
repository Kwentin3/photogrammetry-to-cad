# Подготовка GPU: постоянное ПО и данные задания

24 ноября 2026 реально проверен [Goal #19](../../goal-19.md): GPU получает
закреплённый Meshroom из постоянного источника, принимает локальные входы и
выполняет native video/photo обработку. Runtime не передавался с компьютера.
Обе аренды удалены; backup проверен, native ledger **$0.101**.
Поставка — [PR #20](https://github.com/Kwentin3/photogrammetry-to-cad/pull/20).

## Идентичность и постоянный источник

Неизменённый архив `Meshroom-2026.11.21-b12ea88-linux-full.tar.gz`, 600156630 B,
SHA256 `4ca3cfb0898b8000def4e68d513468a199b948329b63cdb6b257e427d295163b`.
Meshroom `b12ea8896e7e95cc9911b4ec39c272914e4da726`, AliceVision
`d012d05589b528dcf57a2a0c805c0a5709df8613`; image digest закреплён в
`configs/runtime-2026.json`. Прогон использовал точный commit
`5c82a3a2eed73e7f7699e9faa4cd6631f7306ee4`; минимальный source archive 90752 B
содержал scripts/configs/runbook, его SHA совпал до распаковки.

Сначала проверен Release этого публичного репозитория. Actual FFmpeg
libavutil/libavformat/libavcodec содержат `--disable-gpl --enable-nonfree` и
`nonfree and unredistributable`; один MPL2 attribution этого не решает.
Поэтому владелец разрешил отдельный закрытый Release для собственных запусков.
Это не разрешение публичной перераздачи. См. [FFmpeg legal](https://ffmpeg.org/legal.html)
и [native configure flags](https://github.com/FFmpeg/FFmpeg/blob/master/configure#L90-L95).

Оба COPYING совпали с точными upstream commits; архив и уведомления не менялись.
Повторно прочитаны 12486 entries, SHA совпал. Собственные фото/cache/private config
по inventory не найдены; Python test/certdata содержит штатные ключевые fixture.
Это ограниченная проверка содержимого, не полный анализ секретов в бинарниках.

Четыре private assets — архив, SHA sidecar, PROVENANCE и release notes — проверены
и опубликованы до аренды. GitHub digest архива совпал с pin. Native immutability
выключена: версия тега не объявляется неизменяемой. Первичная загрузка архива
с компьютера в постоянный источник заняла **713.984 с**, вне rental clock.
Этот разовый расход не скрывается за последующей быстрой загрузкой на GPU.

Постоянный `runtime-source.private.json` с repository/tag хранится рядом с
резервным архивом в owner-каталоге `photogrammetry-to-cad-work/runtime-archives/`.
Для запуска его копируют в рабочую папку и выполняют канонический resolver
[runbook](../../runbook.md): authenticated API → HEAD/302 → временная signed URL.
На GPU попадает только ссылка, account token остаётся на управляющей машине.
Постоянный адрес, credentials и signed URL в публичный Git не включены.

## Предметные входы и повторное использование

Повторный HTTP-рецепт запускался с новыми job IDs, без short-circuit remote_job.

## Native SFTP: завершённый и прерванный файл

Rclone 1.76.0, SFTP с trusted known_hosts, cutoff16M/chunk4M, прямые native CLI.
Отдельный synthetic probe уменьшен с 64 до **32 MiB** после наблюдения канала
около 0.24 MiB/s, чтобы уложиться в общий срок. Он всё ещё выше cutoff и делится
на восемь частей; оригиналы съёмки не уменьшались. Второй файл — 29 B.

| Переход | Наблюдение |
|---|---|
| Первый copy | 33554461 B, native DEBUG подтвердил восемь потоков большого файла; оба whole-file SHA совпали. |
| Завершённый повтор | Native stats: 0 transferred bytes/0 transfers, оба файла unchanged/skipped. SHA проверен независимо. |
| Прерывание | Native `--max-duration 20s` не завершил клиент за внешний предел 35 с; адресно остановлен именно его PID. Remote holders отсутствовали до повтора. Stats 16384000 B; `.partial` имел logical size32MiB, но неправильный SHA. Размер не означал успех. |
| Первый retry | Восемь потоков одновременно с backup download: exit5, SSH handshake EOF при записи chunk, 34.905 с. Причина на уровне сервера не доказана. |
| Итоговый retry | После окончания другой передачи, четыре потока, полная повторная отправка 33554432 B; exit0, **117.436 с**, SHA совпал, remote holders=[] после завершения. |

SFTP не обещает продолжение с последнего байта: в этом опыте незавершённый файл
передан заново полностью. Оба условия — последовательность и число потоков —
изменены вместе; нельзя приписать исправление только четырём потокам.
Первоначальный failed receipt, EOF и итоговый успешный повтор сохранены.
Для оператора: после timeout проверить свой RunId и remote участников; при EOF
закончить конфликтующую передачу и выбрать подходящий native parallelism/TTL.

## HTTP resume, недоступный источник и резерв

Локально native aria2 1.37.0 Windows использовала тот же conf SHA256
`0c48e7c29545adf5e7e0ea91f1eb0b7513ecf79e7c70ea2493e1e8f2f1f10931`.
Fixture64MiB, четыре фактических Range из доступных восьми streams:
прерывание native stop3/exit7 сохранило `.aria2`; продолжение получило HTTP206,
whole-file SHA совпал. Готовый повтор занял 1.141 с без полной перекачки;
сервер успел отправить 128KiB в socket buffer, это не объявляется нулевым трафиком.
404 дал exit3. Сервер и managed дерево завершены, download-копии удалены.

На Linux/GPU точно тот же отмеченный блок runbook запускался с заведомо
отсутствующим asset в отдельный каталог: native `Resource not found`, exit3,
cleanup confirmed; автоматический bootstrap не начался. Затем явно выбран
проверенный существующий GPU-архив через bootstrap `--archive`: success за 2 с,
probes и cleanup подтверждены. Первая проверочная assertion ошибочно искала
буквальные `404` в log; фактическая aria2 пишет `Resource not found`. Ошибка
проверки сохранена, результат подтверждён native status/log отдельным чтением.
Новая передача 600 MB локального fallback в этой приёмке не выполнялась.
Её рецепт и постоянный SHA-проверенный owner-архив сохранены; SFTP large mode
проверен отдельно. При истечении private signed URL нужна новая ссылка.

## Проверки и граница готовности

78 локальных unittest — OK, два пропуска необязательных PDF-проверок из-за
отсутствия fitz. Проверены UTF-8, 161 локальная ссылка, native config/reader,
15 Bash-блоков и AST 12 PowerShell-блоков runbook; исполняемый runtime-блок

фиксируется в Goal. CI для незатронутых capture/PDF не подменяет эту приёмку.
Новых product downloader/transfer API, patch ядра или отдельного оркестратора нет.

Следующий агент берёт workflow skill, runbook, runtime lock и новую внешнюю
карточку: выбирает fresh/resume, нужные компоненты и оригиналы, разрешает private
source, задаёт пути/native options, проверяет SHA/status/result, сохраняет backup
и освобождает аренду. Полный новый dense, CAD, физический масштаб и свежая съёмка
в #19 не принимались. Общий коэффициент ускорения не установлен.
