# CCTag3: от установки отдельных мишеней к контролю результата

Оператор получает четыре печатные мишени и короткую схему установки; агент
переносит обычный ответ человека в одну рабочую форму. Подтверждённая масштабная
пара доходит до native SfMTransform, остальные пары дают отдельную таблицу
расхождений по центрам меток в координатах выданной геометрии.

Программная поставка [#29](https://github.com/Kwentin3/photogrammetry-to-cad/issues/29)
проверяется локально и CPU-детектором PDF. **Новая физическая съёмка с
распечатанными мишенями не выполнена; физическая точность не подтверждена.**
Новая GPU не арендовалась. Предыдущий разовый бюджет комнаты не переносился.

## Что изменилось

- [Готовый комплект](../../../templates/capture-kit/cctag3-print.pdf): отдельные ID0–3,
  A4, кольца100мм; [схема](../../../templates/capture-kit/placement.txt) задаёт
  план1500мм между ID0–1 и независимый план1000мм между ID2–3. Эти числа пока
  не подтверждены. Для иной сцены ID/пары/длины меняются через CSV `--plan`;
  размер PDF — параметрами генератора. Рейка и прямоугольник не обязательны.
- Неизменный выданный комплект сохраняет SHA. Агент ведёт отдельную рабочую
  копию `measurements.csv`: план, факт, статус, способ, источник подтверждения,
  известная неопределённость. `confirmed_nominal` означает проверенную установку
  по заданию; `measured` использует фактическую длину. Повторный обмер уже
  проверенной установки не требуется. Подтверждение печати подтверждает только печать.
- [Пример Legacy-настроек](../../../configs/reconstruction-cctag.example.json)
  ссылается на форму напрямую. Общий reader выводит масштабную заявку; повторять
  её числа вручную в settings запрещено. Исходная CSV фиксируется SHA при prepare.
  Неподтверждённый масштаб останавливается до runtime; изменение формы требует нового run.
- Существующий export проверяет native post-transform сцену и сохраняет SHA
  именно экспортированных scene/cloud/raw mesh. Report читает эти файлы и
  сверяет обе записи экспортёра, исходную CSV и фактическую масштабную базу.
  Для нового known-scale CSV отчёта mesh обязателен. Это привязка к сохранённому
  выводу экспортёра, не независимое доказательство подлинности произвольных receipts.
- Report выдаёт JSON всех строк и читаемый Markdown через `--table`.
  Отсутствующие/неоднозначные/слабо наблюдаемые центры и неподтверждённые длины
  остаются явно непроверенными. Старые вводы без CSV и работа без масштаба сохранены.

Владельцы смысла: `capture_measurements.py` — форма и подтверждение;
`check_marker_scale.py` — native ID/наблюдения/расстояния;
`reconstruction.py` — native граф и экспорт;
`reconstruction_report.py` — их сопоставление. Новых детектора, UI, оркестратора,
подгонки по контрольным парам и распознавания углов объекта нет.

## Что проверено

Локальный полный набор: **99 проверок, PASS, 5 пропущены** из-за optional
capture-зависимостей/неуказанного SVG-source в геометрическом окружении.
В существующем отдельном capture-окружении **11/11 PASS без пропусков**:
реальная генерация A3, ID7/23/31/5, масштабная пара7–31 (не первые два ID),
другие длины, отсутствие предварительного подтверждения, отдельная рабочая CSV,
сохранение SHA выданного комплекта. Геометрическое окружение — Python3.11;
capture — Python3.11.9, ReportLab4.5.1, svglib1.6.0, svgwrite1.4.3,
PyMuPDF1.26.5. Просмотр конечного PDF и native CPU-квалификация описаны ниже.

Существенные отрицательные проверки: план и подтверждённая печать не дают
масштаб; отличающаяся фактическая длина заменяет план; изменение CSV после
prepare обнаруживается; масштабная пара не может объявляться своим независимым
контролем. Подмена actual scene даже с пересчитанным scene SHA не проходит
проверку базы. Изменение самих PLY/OBJ, неверные единицы, пропуск export binding,
отсутствующая mesh и несовпадение relocated CSV отклоняются. Unknown scale
никогда не получает `model_mm`. Неизвестная погрешность остаётся `null`.

Сохранённые **actual native JSON Goal #4** проверены новым общим численным
helper: ID0–1, по10 наблюдений от восстановленных камер,
`0.4801067056395096` условных единиц → `100.0` **синтетических** мм,
ошибка переноса0, численный допуск0.000002. SHA до:
`6638ede788ff60dc818f5e9674b7c8ca47ba470adb2e6dc1fa43709e05e62eda`, после:
`10c072d0957aa437b494ae91a5554aa98f87fef41be30790712632e8e0140edf`.
Других ID там нет: независимый контроль не выполнен. Исторический transform
был `from_markers`, включая поворот/перенос; ему не приписывались новые
CSV/effective/export receipts. Этот probe проверяет чтение реального native
формата и численный helper, а не новый сквозной опыт CSV→физическая съёмка→dense.

### Читаемый пример таблицы

Ниже сокращённый результат **программного fixture**, выполненный настоящим
report CLI с `--table --tolerance-mm 0.1`. Источник —
[`measurement_sheet` и `bind_measurement_export`](../../../tests/test_reconstruction_report.py).
Координаты, подтверждения `operator reply fixture`, applied/export записи,
небольшие бинарный PLY и OBJ созданы тестом; это не замер комнаты и не native
экспорт. JSON содержит8 строк, пути/SHA actual входов, наблюдения, способы и
источники подтверждения; итог `attention_required`, CLI успешно сформировал отчёт.

| Пара / роль | План, мм | Подтверждено, мм | Модель, мм | Δ, мм | Состояние |
|---|---:|---:|---:|---:|---|
| ID2–5, масштаб | 2 | 2, установка по заданию | 2 | 0 | Масштаб численно применён |
| ID2–7, контроль | 3 | 2.5, фактическая длина | 3 | +0.5 | Вне заданного допуска0.1мм |
| ID2–9, контроль | неизвестно | 9 | неизвестно | неизвестно | Центр отсутствует |
| ID2–8, контроль | неизвестно | 1 | неизвестно | неизвестно | Мало наблюдений |
| ID2–6, контроль | неизвестно | 4 | неизвестно | неизвестно | Повторный ID |
| ID5–7, контроль | 17 | не подтверждено | 3.60555 | неизвестно | План не принят за замер |
| Печатная/ручная опора | 100 / неизвестно | не подтверждено / 4 | неизвестно | неизвестно | Нет автоматической 3D-точки |

Неопределённость входа во всех строках неизвестна. Даже её искусственное
увеличение до99мм не делает контроль+0.5мм прошедшим заданный допуск0.1мм.
Масштаб задаёт только ID2–5; ID2–7 его не меняет. Совпадение масштабной пары —
проверка переноса коэффициента, а не независимая проверка точности.

## Самопроверка по заданию

| Вопрос | Ответ |
|---|---|
| 1. Сохранён процесс человека? | Да: отдельные мишени, подтверждение установки по плану либо фактические длины, обычный чат. Рейка/повторный обмер/углы не обязательны. |
| 2. Может ли план стать фактом? | Только явный `confirmed_nominal` со способом и источником. Пропущенная контрольная пара остаётся unverified; неподтверждённая база блокирует known-scale. Actual1487 вместо плана1500 даёт1487. |
| 3. Откуда 3D-точка? | Native CCTag3 color-ID→уникальный landmark.X с минимум двумя наблюдениями от восстановленных камер. Missing/duplicate/weak показаны, лучший кандидат не угадывается. |
| 4. Проверяется выдача? | Actual post-transform scene + оба export binding для scene/cloud/mesh, CSV SHA/смысл и повторный численный расчёт базы. Метки не становятся углами объекта; проверка центра не доказывает точность всех mesh-поверхностей. |
| 5. Независим контроль? | Да: коэффициент выводится из одной scale-строки. Остальные пары только сравниваются; та же пара в роли check отвергается. |
| 6. Что означает разница? | Δ=модель−подтверждённая длина. Неопределённость замера, численный допуск SfMTransform и опциональный допуск результата разделены. Δ сама по себе не устанавливает причину ошибки. |
| 7. Что упрощено? | Штатные SVG/CCTag3/Legacy/SfMTransform и существующие export/report; один небольшой reader формы. ID/пары/длины/пути через данные, без нового распознавателя или платформы. |
| 8. Продолжит ли другой агент? | Да: [operator](../../operator.md), [capture](../../capture.md), [runbook](../../runbook.md#подтверждённые-расстояния-cctag3), пример settings и frozen CSV. План, подтверждение, расчёт и физическая непроверенность различены. |

## Что нужно для физического опыта

1. Распечатать комплект при100%, проверить X/Y, установить мишени неподвижно
   по схеме и обычным сообщением подтвердить пары/способ/известную точность;
   фактические отличающиеся длины подходят.
2. Передать3–5 оригинальных пробных фото с разных точек и рабочей дистанции;
   после проверки читаемости — перекрывающийся обход с параллаксом.
3. Для платного нового запуска нужен отдельный бюджет. Его результат —
   измеренные расхождения независимых пар и осмотр покрытия; заранее обещанных
   1–2мм или готовности к изготовлению нет. CAD остаётся отдельным этапом.
