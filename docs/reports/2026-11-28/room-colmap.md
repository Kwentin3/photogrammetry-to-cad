# Проверка COLMAP на 77 фото комнаты

Из тех же 77 фотографий получено второе цветное облако, 1 143 370 точек.
В облаке AliceVision было 938 649. На двух проблемных участках замена метода
не решила задачу. У освещённой стены итоговое покрытие упало, а в проёме
стула осталась группа точек перед ожидаемым фоном. Для этой комнаты сохраняем
AliceVision и доснимаем два участка. О качестве остальных поверхностей это
сравнение заключения не даёт.

## Штатный экспорт и камеры

Для оригинальных JPEG нужен исходный `SfMTransform/sfmExpanded.usda` вместе
с его соседним `sfmExpanded_landmarks.usdc`. В сцене принята одна камера
`pinhole` с `distortionType=radialk3`. Штатный `aliceVision_exportColmap`
экспортировал её как COLMAP `FULL_OPENCV`: `fx fy cx cy k1 k2 0 0 k3 0 0 0`.
Это фактически проверенный маршрут, дополнительная конверсия модели камеры
не потребовалась.

Пути к фотографиям в переносимой копии сцены должны указывать на доступные
исходные JPEG; менять геометрию и параметры камеры при этом не нужно.
Относительный USD payload также должен остаться доступным. Сначала установить
`ALICEVISION_ROOT` на корень принятого runtime. Пример обычного CLI:

```sh
aliceVision_exportColmap --input "$SCENE" --output "$EXPORT" --copyImages true --maxCoresAvailable 2
python scripts/repair_colmap_tracks.py --input "$EXPORT/sparse/0" --output "$FIXED/0" --receipt "$RECEIPT"
python scripts/repair_colmap_tracks.py --input "$FIXED/0"
```

`IntrinsicsTransforming/sfmData.usda` имеет уже другую камеру: pinhole без
искажений. Сочетать её с оригинальными JPEG неправильно. Этот вход требует
соответствующих штатных undistorted изображений. Для текущей проверки выбран
экспорт исходной radialk3-сцены и последующий штатный COLMAP `image_undistorter`.

## Обнаруженное расхождение и узкий ремонт

Штатный text export сохранил 77 камер, 30 012 точек и 85 556 наблюдений, но
`POINT2D_IDX` в `points3D.txt` не соответствовали порядку observations в
`images.txt`. PyCOLMAP 4.2.1 отверг исходную модель при проверке взаимных ссылок.
По этому наблюдению нельзя утверждать внутреннюю причину ошибки экспортёра.

[Скрипт](../../../scripts/repair_colmap_tracks.py) восстанавливает только индекс:
для каждой пары `IMAGE_ID / POINT3D_ID` находит единственное наблюдение с тем же
point ID и использует его позицию в строке изображения. Дубли, отсутствующие
наблюдения, отсутствующие обратные tracks и повторные пары приводят к отказу.
Скрипт требует отдельный пустой output; исходный экспорт сохраняется.

`cameras.txt` и `images.txt` копируются побайтно. В `points3D.txt` сохраняются
исходные ID, XYZ, RGB, ERROR и IMAGE_ID; меняются только `POINT2D_IDX` и
форматирование пробелов. Никакой оптимизации, пересчёта поз, точек или XY нет.
`ERROR=-1` пришёл из штатного экспортёра и не является оценкой reprojection error.

## Проверка и receipt

На фактическом экспорте изменены 85 537 из 85 556 индексов. Проверены все
обратные связи, соответствие SHA256 всех 77 JPEG исходникам и позы относительно
исходной сцены. Максимальная абсолютная разница коэффициентов вращения составила
около `1.1e-15`; трансляции согласованы с точностью округления text export.
PyCOLMAP 4.2.1 загрузил исправленную модель: `is_valid=True`, 77 images,
30 012 points3D, 85 556 observations.

Скрипт пишет обезличенный JSON receipt: числа изображений/точек/tracks,
количество заменённых индексов, SHA256 трёх исходных и трёх выходных файлов,
подтверждение неизменности cameras/images и взаимных ссылок. Пути и имена
фотографий в receipt не попадают. Для нативной приёмки в отдельном окружении
с установленным PyCOLMAP:

```python
import pycolmap
model = pycolmap.Reconstruction(fixed_model_directory)
assert model.is_valid()
print(model.num_reg_images(), model.num_points3D(), model.compute_num_observations())
```

Поставляемая копия скрипта повторно выполнена на реальном штатном экспорте
в отдельной приватной папке: изменены 85 537 индексов, проверены все 85 556
взаимных ссылок. Повторный check дал ноль изменений. PyCOLMAP 4.2.1 загрузил
её с `is_valid=True`: 77 registered images, 30 012 points, 85 556 observations.
SHA256 `cameras.txt` и `images.txt` точно совпали с исходным экспортом и ранее
принятой исправленной моделью. `points3D.txt` совпал с принятой исправленной
моделью побайтно после единственного CRLF → LF; переносимый скрипт пишет LF.
Receipt содержит SHA256 всех трёх входных и выходных файлов без частных путей.

Нативный text export округляет часть чисел примерно до шести значащих цифр.
Ремонт индексов это округление не исправляет. Корректный граф sparse не доказывает
качество dense, физический масштаб, метрическую точность или пригодность CAD.
## Проверка проекций и расчёт глубины

SHA-256 всех 77 JPEG совпал с исходной съёмкой. Для проверки положения камер
взяли исходную сцену AliceVision с radialk3. После переноса центры камер
разошлись максимум на 4·10⁻¹⁵ единиц сцены. В контрольных точках на фото
отклонение составило до 0,0043 исходного пикселя, на сетке по всему кадру —
до 0,005 пикселя. Обе реконструкции используют одну систему координат.

Расчёт выполнен штатными вызовами PyCOLMAP 4.2.1. После устранения дисторсии
получились 77 кадров 2080 × 1542. Длинная сторона соответствует разрешению
карт глубины AliceVision. Для каждого кадра COLMAP сам выбирает до десяти
соседних по общим наблюдениям. Шаг окна 2 уменьшает время расчёта.

```python
import pycolmap as c

c.undistort_images(
    workspace, fixed_model, original_images, num_patch_match_src_images=10,
    undistort_options=c.UndistortCameraOptions(max_image_size=2080),
    jpeg_quality=95, num_threads=1,
)
patch = c.PatchMatchOptions(gpu_index="0", window_step=2, geom_consistency=True,
                            filter=True, cache_size=6.0, num_threads=6)
c.patch_match_stereo(workspace, options=patch)
fusion = c.StereoFusionOptions(num_threads=6, cache_size=6.0, use_cache=True)
c.stereo_fusion(fused_ply, workspace, input_type="geometric",
                options=fusion, output_type="ply")
```

Здесь `workspace` и `fused_ply` — пути для плотной реконструкции и выходного
облака, `fixed_model` — исправленная модель, `original_images` — каталог
исходных JPEG. Для PatchMatch на Linux использована готовая сборка
[`pycolmap-cuda12`](https://github.com/colmap/colmap/blob/4.2.1/python/README.md).

## Что видно до слияния карт

Для того же исходного фото и участка стены, что в [предыдущей проверке комнаты](https://github.com/Kwentin3/photogrammetry-to-cad/pull/45),
проверили 115 600 позиций. AliceVision сохранил глубину в 32 321 позиции
(28,0%), COLMAP — в 37 468 (32,4%). Это доля позиций на выбранном участке
одного ракурса. У других ракурсов своё покрытие.

Для стула спроецировали исходный луч в карту COLMAP. Ближайший отсчёт
перевели из глубины по оси камеры в расстояние вдоль соответствующего луча.
Расстояния указаны в единицах сцены. Положение дальнего фона оценено по
соседним исходным точкам. На отложенных точках 95-й процентиль расстояния до
плоскости составил 0,025, а внутри проёма приходится её экстраполировать.

| Луч в исходном кадре | AliceVision | COLMAP | Оценка дальнего фона на луче COLMAP |
|---|---:|---:|---:|
| B, внутри проёма | 1,747 | 1,763 | 1,872 |
| C, внутри проёма | 1,910 | 1,932 | 1,914 |
| R, на ободе | 1,690 | 1,695 | 1,782 |

В точке B оба метода поставили поверхность перед ожидаемым фоном. В точке C
глубина согласуется с оценкой фона. На ободе R ближняя поверхность ожидаема.
Для луча A COLMAP отфильтровал центральный отсчёт. В небольшом круге вокруг
него осталось 11 из 29 отсчётов. Эти соседи не определяют глубину в центре.

## Что попало в плотное облако

Оба облака спроецировали на исходный кадр в исходных осях. Использованы
заранее выбранные маски, ячейки по 2 исходных пикселя, одинаковое правило
выбора переднего слоя и одна опорная плоскость стены. Дополнительное
выравнивание облаков не потребовалось.

| Участок | AliceVision | COLMAP |
|---|---:|---:|
| Стена, занятые ячейки в фиксированной области | 3 852 | 614 |
| Проём стула, передние точки в кругах A / B / C | 1 / 6 / 5 | 0 / 12 / 0 |
| Медианная дальность переднего слоя у B | 1,745 | 1,761 |
| Обод R, передние точки | 5 | 3 |

На стене COLMAP сохранил 16% от числа ячеек, занятых AliceVision. Некоторые
сильные выбросы исчезли, но вместе с ними исчезли и большие участки видимой
поверхности. Именно здесь небольшое преимущество на карте одного ракурса
обернулось потерей покрытия после слияния.

У B сохранились 14 точек COLMAP суммарно по слоям. Для каждой в штатном
`fused.ply.vis` указано от 3 до 6 камер, у восьми есть поддержка сразу двух
выбранных соседних видов. Тем не менее ближняя группа расходится с оценкой
дальней панели. В A и C у COLMAP пропало покрытие. По пустоте облака в этих
точках нельзя подтвердить форму проёма.

**Решение для следующей съёмки.** Стену доснять при рассеянном свете, с
перекрытием кадров и деталями вокруг засвеченного участка. Спинку стула
снять с нескольких боковых положений и высот так, чтобы контур проёма
смещался относительно видимого сквозь него фона. Те же области на новой
съёмке проверить до построения сетки. Оснований переснимать всю комнату
по этим двум участкам нет.

## Сохранённый результат

Частный `fused.ply` содержит координаты, нормали и RGB для 1 143 370 точек.
SHA-256 файла — `ab065919795e11aafb7ffee5d98ebaf43010b69245d31b735d228c244b57a331`.
Проверены соответствующие записи видимости всех точек, имена камер и
контрольные суммы выгрузки. Сохранены 77 карт геометрической глубины, 77 карт
нормалей, параметры, журнал и иллюстрации по исходным фотографиям.

На одной RTX 4090 PatchMatch занял 14 мин 18 с, слияние — 3 мин 3 с.
От запроса аренды до подтверждённого удаления инстанса прошло 29 мин 22 с.
На момент проверки в 18:10 UTC провайдер отразил $0,154 при разрешённом
лимите $1. Проводки могут поступать позднее.
