# Участок стены напротив окна

Из сохранённой сцены комнаты восстановлен открытый участок деревянной панели под полкой. Старую модель взяли из [поставки с текстурами](https://github.com/Kwentin3/photogrammetry-to-cad/pull/41). Результат — отдельный OBJ в тех же координатах, материал MTL и одна PNG-текстура. В локальной выдаче есть исходное фото, цветное сравнение в одной камере, косой вид без текстуры и исходные данные для повторения. Физический масштаб неизвестен.

## Что получилось

В двух снимках вручную обвели видимую облицовку. Полка, стул и принтер находятся за границей выбранной области. Из 584 106 точек облака 2 505 прошли отбор по обеим проекциям и глубине. Для подгонки Open3D использовал 2 004 точки, из них 1 692 поддержали плоскость. На 501 отложенной точке медиана расстояния до плоскости — 0,00442, 95-й процентиль — 0,01653 в единицах сцены. На этом участке допущена плоская аппроксимация. Наружные стыки облицовки, мебель и скрытая часть стены остаются в исходной модели.

Из опорных точек вырезали прямоугольник внутри обеих размеченных областей. Обе грани повёрнуты к камерам съёмки. В UV-развёртку перенесли цвет из одного снимка с различимой фактурой. Солнечное пятно видно на другом кадре этого же участка. В нём ни один пиксель внутри контура не достиг 250 одновременно во всех трёх каналах. Эти данные позволяют отличить локальный свет от полного выбеливания JPEG. Причина пятен на других поверхностях комнаты остаётся неизвестной.

В независимом ракурсе на старой сетке видны разрозненные треугольники и слишком светлая полоса. На новой читаются непрерывные ряды древесины. Средняя абсолютная разница цвета с контрольным JPEG по каждому каналу снизилась с 50,9 до 2,8 из 255 на 6 171 пикселе внутри общего контура (вид 1200 × 900). На более тёмном контрольном фото разница снизилась с 90,7 до 52,2. Текстура хранит освещение выбранного снимка.

Дополнительная проверка по исходным снимкам шириной 4160 пикселей дала 50 взаимных соответствий SIFT с отношением расстояний < 0,72. На независимом ракурсе медианное расхождение при проекции через плоскость — 1,12 пикселя, максимальное — 4,39. Этот вид выбран за различимую фактуру. В более тёмном контрольном снимке уверенных соответствий не нашлось. Результат относится к данному участку и сохранённым камерам.

## Повторение на сохранённом проекте

Требуются Python, Open3D, NumPy, SciPy и Pillow. Проверено с Open3D 0.20.0 на Windows. Нужны dense PLY, экспорт камер AliceVision в JSON и оригинальные JPEG от той же реконструкции. Поддерживаемая камера — pinhole с radialk3 и квадратными пикселями. Облако и камеры используют одну систему осей; при записи AliceVision OBJ меняются знаки Y и Z. Порог RANSAC и отступ по глубине задаются в единицах исходной сцены.

```powershell
python scripts/fit_visible_patch.py --cloud dense.ply --scene scene.json --selection selection.json --threshold 0.012 --out-dir fit
python scripts/texture_plane.py --scene scene.json --plane fit/plane.json --photo $photo --out-dir model
```

В переменную `$photo` запишите путь к исходному снимку. Для повторения именно этого результата используйте selection.json из локального комплекта и JPEG, указанный в README комплекта. Вход selection.json содержит массив `views`. Две записи с ролями `fit1` и `fit2` задают разные зарегистрированные снимки и упорядоченные выпуклые `normalized_polygon` в координатах исходного фото от 0 до 1, начало в левом верхнем углу. Необязательная запись `holdout` задаёт контрольную область. Укажите одну видимую поверхность без перекрытий и разных слоёв. Отбор по ближайшей глубине в ячейках 4 пикселя с отступом 0,03 проверен на масштабе этой сцены.

Результат открывается из `model/panel.obj` с лежащими рядом `panel.mtl` и `panel-texture.png`. В `fit/plane.json` сохранены исходные хэши, положение плоскости, опорные точки по количеству, контур и отклонения. Стул и панель вручную различены по фото. Граница экспортированного прямоугольника обозначает предел пилота; для восстановления всей стены потребуется отдельная разметка её видимых границ и выступов.
