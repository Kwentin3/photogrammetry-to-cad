# Goal #8 — Meshroom harness: фото/видео → облако и mesh

Источник: [issue #8](https://github.com/Kwentin3/photogrammetry-to-cad/issues/8)
и комментарий постановки. Начато и завершено 22 ноября 2026. Статус: **PASS**.
Поставка опубликована в [PR #10 к main](https://github.com/Kwentin3/photogrammetry-to-cad/pull/10),
PR открыт и не влит; main содержит принятую базу #7, а новая дельта — в PR #10.
Это единственная текущая запись задачи; Goal #6 остаётся историей принятой базы.

## Результат и границы

Агент по репозиторию выбирает релевантный штатный сценарий Meshroom, меняет
входы/настройки без правок исходников под объект, получает плотное облако и
отдельную настоящую сетку, понимает ограничения и способы продолжения графа.
Обязательны устранение найденных пробелов и фактический тест другим агентом
без истории чата. CAD, распознавание деталей, другие фотограмметрические стеки,
новый оркестратор и освоение отдельных доменов (например LiDAR) не входят.

Новые расходы на инфраструктуру — **$0**. Начинаем с принятого backup/runtime;
новая аренда допустима только при конкретном необходимом блокере и достаточном
отдельном допуске. Сырые данные и частные рабочие карточки остаются вне Git.

## Найденные пробелы и выбранные срезы

1. `prepare` безусловно удаляет Texturing/MeshFiltering/CopyFiles, хотя уже
   используется native `--toNode`. Проверить и сохранить штатный граф, раскрыть
   имена конечных узлов; последующее продолжение зависит от кэша/входов/UID.
2. `export` выдаёт scene.json/dense.ply, но не отдельный Meshing.outputMesh.
   Сначала найти фактическую сетку принятого расчёта по native project/UID,
   прочитать и проверить её вместе с облаком; не подменять одним другое.
3. Дополнить существующую карту релевантного домена и компактный перечень
   остальных шаблонов. Согласовать README/AGENTS/context/runbook с этой картой.
4. Минимально исправить найденные стыки и проверить новым независимым агентом
   запросы «облако», «та же съёмка → mesh», «объект с переворотом».

## Приёмка

- Релевантные возможности доступны через настройки/штатные рецепты; ясны данные,
  ресурсы, дополнения, выходы, проверенность и ограничения.
- Прежний простой путь сохранён; граф не урезан без причины; глубина определяется
  native узлом. Сглаживание отделено от удаления фрагментов и точности.
- Облако и mesh одной реконструкции реально прочитаны, сохранены пути/хэши,
  vertices/faces/конечность координат и единицы/система координат.
- Другой агент без истории чата выполнил доступную выдачу первых двух результатов
  и выбрал конкретный native рецепт для третьего, честно назвав недостающие входы.
- Независимая итоговая приёмка, публикация проверенного PR к main, безопасная
  уборка собственных временных ресурсов. Новые вычисления и чтение старого кэша
  различимы в отчёте; готовность неподтверждённых режимов не заявляется.

## Проверенное состояние

- Оба native OBJ найдены по сохранённому Meshing output/UID, прочитаны Open3D
  вместе с dense PLY, SHA совпали с backup-index до/после. Standard native
  121293v/241137f, Legacy121513v/241387f; все координаты и индексы валидны.
  Open3D объединяет совпадающие вершины: 118788/119022v при тех же faces.
- Найдена и подтверждена pinned C++ исходником разница осей: OBJ хранит `(x,-y,-z)`,
  SfMData PLY — XYZ. Фиксированный R=diag(1,-1,-1) сопоставляет выводы без fit
  и изменения единиц. Raw файлы сохранены; физическая шкала unknown.
  [Отчёт, просмотр и JSON](reports/2026-11-22/meshroom-harness.md).
- Новый prepare сохраняет полный шаблон с keepOutputNodes=True; endpoint names
  берёт из native графа, --toNode выбирает глубину. Export выдаёт отдельный raw mesh
  и source/SHA, report необязательно читает mesh и отражает оси/единицы.
- Для новой конфигурации доступен явный native --cache, без нового слоя кэша;
  общий cache используется только последовательно после подтверждённой остановки.
- Найден ещё один конкретный config gap: Standard затирал явные SfMTransform
  settings. Identity default сохранён, явные native поля теперь применяются;
  handoff проверен локально, новый orientation compute не объявлен выполненным.

  все прежние UID (15/15,9/9). Meshing SUCCESS пропущен, для Texturing запланированы
  только filtering/texturing, у Legacy ещё PDS. Это core planner с частью native
  CompatibilityNodes (нет Linux pyalicevision в Windows), не новый AV compute.
- Карта охватывает все релевантные сценарии и остальные 22 из 27 шаблонов;
  advanced/addon/невычисленные режимы имеют явные статусы. Runbook/README/AGENTS/
  context согласованы, старые отчёты не переписаны.
