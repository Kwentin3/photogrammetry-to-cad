# Goal #19: подготовка GPU с переиспользованием ПО

Задание: [issue #19](https://github.com/Kwentin3/photogrammetry-to-cad/issues/19).
Статус: реализация и подготовка проверки; реальная GPU-приёмка ещё не выполнена.

## Результат и границы

GPU получает закреплённый Meshroom из постоянного облачного источника; локальный
workspace передаёт данные выбранного задания штатным rclone. Источники, пути,
состав, режим и параметры задаются конфигурацией и native CLI. Свежий запуск
не требует прежнего baseline. Фото/видео, продолжение и отключаемые ML-компоненты
сохраняют существующих владельцев. Новый транспорт, оркестратор, полный dense
пересчёт, CAD и смена версии runtime в эту поставку не входят.

## Принятый путь

- Первым проверен GitHub Release этого репозитория. Публичное зеркалирование
  пока исключено: actual FFmpeg библиотеки включают `--enable-nonfree` и строку
  `nonfree and unredistributable`. Один MPL2 attribution не закрывает этот вопрос.
  Предложенный запасной путь — закрытый Release владельца для его личных запусков,
  временная подписанная ссылка передаётся GPU без GitHub account token.
  Создание закрытого источника ещё не согласовано и не выполнено.
- Сохраняются те же байты: 600156630 B / SHA256
  `4ca3cfb0898b8000def4e68d513468a199b948329b63cdb6b257e427d295163b`.
- Конфигурация runtime владеет версией/URL/SHA; aria2 — доставкой и продолжением;
  существующий bootstrap `--archive` — проверкой и установкой; reconstruction
  и video_frames — предметными входами/обработкой; rclone — передачей данных.
- Запасной источник выбирается явно для тех же байтов, без `latest` и скрытой
  смены сборки. Локальная постоянная копия сохраняется.
- Реальные API-права на репозиторий подтверждены. GitHub release immutability
  сейчас `enabled=false`, `enforced_by_owner=false`; имя тега не выдаётся за
  неизменяемость. SHA обязателен независимо от этой настройки.

## Проверенное состояние

- Рабочая копия изолирована в `issue-19/checkout` вне основной папки, ветка
  `goal/19-gpu-preparation`, база `22f4c20`. Чужие ветки и worktree сохранены.
- Архив повторно прочитан, SHA совпал, 12486 записей. Собственных фото/кэша и
  частных конфигов по inventory нет; совпадения ключевых markers относятся
  к Python test/certdata. Это ограниченная проверка, не полный анализ бинарников.
- Оба COPYING совпали с exact upstream commits. Фактический blocker публичного
  mirror: libavutil/libavformat/libavcodec с `--enable-nonfree`. Условия FFmpeg:
  [official checklist](https://ffmpeg.org/legal.html),
  [configure licensing options](https://github.com/FFmpeg/FFmpeg/blob/master/configure#L90-L95).
  Лицензионные файлы и уведомления не менялись; частный audit сохранён вне Git.
- Подготовлен неизменённый MOV и три сохранённых JPEG (18330339 B), отдельно
  два native transport-probe файла, включая 64 MiB для проверки многопоточности.
- Native Vast CLI 1.11.2: активных инстансов нет; найдены совместимые direct
  RTX3090 офферы с `inet_down>=500`, около $0.20/ч. Это снимок предложений,
  не бронь, разрешение расходов или доказательство будущей скорости.
- Платные ресурсы #19 не создавались. Отдельный бюджет #19 ещё не согласован;
  старые бюджеты #6/#12 его не заменяют.
- Обновлены native aria2-конфиг, executable runbook, rclone recipes, skill и
  карточка; новый downloader/transfer API не добавлялся. Заголовочный GitHub
  API→signed URL переход отрепетирован на публичном asset: 302, бинарник не
  скачивался. Private source ещё не создан и не проверен.
- Локальные unittest: 78, OK, 2 пропуска необязательных PDF-проверок (нет fitz
  в этой среде). Проверены UTF-8/links, Bash syntax и 11 PowerShell blocks;
  фактический reader допускает URL override при пустом основном URL.
- Подготовлены private release notes, точный archive и план одной проверки:
  до $0.60/ч с диском, 1 час от create, $1 суммарно с трафиком, stop через 45
  минут и 15 минут резерва на backup/destroy. Это предложение, не разрешение.
  Состояние и пробелы — в [отчёте подготовки](reports/2026-11-24/gpu-preparation.md).

## Обязательное до завершения

1. Проверить фактический архив, происхождение и уведомления; подготовить постоянный
   источник и закрепить адрес без подмены принятой сборки.
2. Реализовать минимальную конфигурационную связку с native downloader, обновить
   существующие skill/runbook/инфраструктуру и карточку запуска.
3. До аренды подготовить точный ограниченный прогон и получить недостающий бюджет.
4. На одной GPU проверить cloud download → bootstrap → native обработку локальных
   входов, повторное использование и смену конфигурации; отдельными native CLI
   проверить завершённый и незавершённый файл, включая большой файл.
5. Зафиксировать отдельно loading, получение/проверку/установку ПО, передачу данных
   и общий срок с учётом перекрытия. Сохранить результаты до удаления своей GPU,
   проверить фактическое освобождение и расходы.
6. Провести содержательную приёмку и необходимые проверки, опубликовать поставку
   и отчёт; убрать только свои временные ресурсы после сохранения результата.

Следующий шаг: закончить конфигурацию/инструкции и локальную репетицию; затем
одним запросом согласовать закрытый источник и ограниченный GPU-бюджет.
