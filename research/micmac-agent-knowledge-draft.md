## 1. Карта решений управляющего агента (сценарий: прямой CPU-вызов `mm3d`)

| Что должен понимать агент | Рабочее правило |
|---|---|
| **Когда обращаться к инструменту** | **Только в двух случаях:** (1) нужна независимая CPU-проверка калибровки/дисторсии (`FraserBasic` / `RadialStd` / `FishEyeEqui`) на `10–45` резких оригинальных фото за `$0` GPU при подозрении на изгиб/неточность калибровки; (2) нужно плотное CPU-облако `.ply` на малом участке (`10–40` фото) без доступа к CUDA GPU. **Не обращаться**, если нужны автоматические `CCTag3` (#29/#30), если в кадре смаз/нет параллакса/пропущены ракурсы (тогда нужна досъёмка), или если фото > 60–80 шт. в полном разрешении (лучше основной GPU-маршрут AliceVision). |
| **Что собрать до запуска** | Проверенные оригиналы одного фиксированного фото-режима (один объектив, одно разрешение `W×H`, без зума и без смешения фото с видео), EXIF (`Model`, `FocalLength`, `FocalLengthIn35mmFilm`), версию и SHA бинарника `mm3d` (`v1.2.0`), доступные лимиты CPU/RAM/процессов, цель проверки (только SfM/калибровка или также `C3DC`). Отметить явно: физический масштаб в самостоятельном `mm3d` без ручного `SBGlobBascule` — **`unknown`**. |
| **Как вызвать** | В **новом пустом ASCII-каталоге** `$WORK/micmac-<run-id>/` (вне Git), с `<NbMaxProc> 2 </NbMaxProc>` (или по лимиту среды) в `MM-Environment.xml`, обязательными флагами `@ExitOnBrkp @ExitOnWarn @ExitOnNan`, без `\.` в Windows-шаблоне имён. Конкретный рецепт — в разделе 3 ниже. |
| **Что читать после запуска** | `Ori-<Out>/AutoCal_*.xml` (фокус `F`, главная точка `PP`, `SzIm`, коэффициенты дисторсии), `Ori-<Out>/Residus.xml` (последний блок `<Iters>`: `AverageResidual`, по каждому кадру `Residual`, `PercOk`, `NbPts`, `NbPtsMul`), число созданных `Ori-<Out>/Orientation-*.xml` vs число входных фото, `AperiCloud_<Out>.ply` (охват камер и разреженное облако) и, если запускался `C3DC`, `C3DC_<Mode>.ply` (заголовок, конечность координат, визуальный осмотр в `Open3D`/`CloudCompare`). |
| **Что означают показатели** | `rc=0`, высокая доля камер, `AverageResidual < 0.5–1 px` и `100k+` точек подтверждают **только внутреннюю самосогласованность расчёта**. Они **не доказывают** физический масштаб, отсутствие изгиба («банана») и точность кромок проёма. Числа всегда совмещать с визуальным осмотром `AperiCloud`/`C3DC` рядом с исходными кадрами и независимыми замерами. |
| **Как действовать при проблеме** | 1) Упал `Tapioca` / мало пар → проверить резкость/перекрытие исходников, шаблон имён (без `\.` на Windows), размер `Tapioca` (`800` → `1500`). 2) `Tapas FraserBasic` расходится на малом/плоском наборе → попробовать более простую модель `RadialStd` / `RadialBasic` в новом `Out=...` (не перезаписывая старый `Ori-*`). 3) Лимит процессов/памяти → снизить `<NbMaxProc>` в `MM-Environment.xml`, поднять `ZoomF` (`4` вместо `2`) или вернуться к GPU-маршруту AliceVision. 4) Дефект вызван отсутствием ракурсов/смазом → **остановить перебор параметров** и выдать оператору точечное задание на досъёмку. |
| **Что сообщить человеку** | 1) Что именно выполнено (`mm3d v1.2.0` на CPU, число ориентированных кадров, `AverageResidual`, полученные `.ply`). 2) **Честный статус масштаба и точности** по 4-ступенчатой шкале (раздел 2). 3) Наблюдаемые пропуски/дефекты геометрии. 4) Только минимально необходимые действия оператора (например, какие 2–3 ракурса доснять или какие независимые промеры нужны). |

## 2. Шкала состояний точности (обязательно различать)

Маленькая ошибка репроекции (`0.3 px`), 100% зарегистрированных камер, большое облако точек и `exit code 0` **не доказывают точность физических размеров**. Агент всегда разделяет 4 разных состояния:

1. **`INTERNAL_ONLY` (`scale = unknown`)** — камеры сошлись, облако построено в условных единицах. Пригодно для визуальной оценки охвата и относительных пропорций; миллиметры называть запрещено.
2. **`SCALED_SINGLE_BASE`** — масштаб задан по одной подтверждённой базе (например, `CCTag3 0–1` в AliceVision или `SBGlobBascule DistFS` в MicMac). Единицы стали метрическими, но **отсутствие изгиба и ошибка на удалённых участках ещё не проверены**.
3. **`CONTROL_CHECKED`** — проверены независимые контрольные расстояния (не участвовавшие в масштабировании/подгонке), зафиксированы `diff_mm`, `diff_pct` и вклад неопределённости замера базы (`uncertainty_mm`). Подтверждает точность каркаса камер в проверенных зонах.
4. **`GEOMETRY_EDGE_CHECKED`** — проверены реальные физические размеры граней/проёмов объекта (ширина, высота, диагонали) по облаку/плоскостям против независимых замеров рулеткой/лазером. Только этот уровень приближает результат к пригодности для CAD/изготовления.

## 3. Воспроизводимый штатный CPU-рецепт (`mm3d v1.2.0`)

Использовать **новый пустой ASCII-каталог** `$RUN` (на Windows при не-ASCII пути использовать ASCII-папку или 8.3 short path). Предварительно проверить `mm3d CheckDependencies` и при жёстком лимите процессов/RAM добавить `<NbMaxProc> 2 </NbMaxProc>` в `<micmac_root>/include/XML_MicMac/MM-Environment.xml`.

```bash
# Linux / Git Bash (для Windows в шаблоне НЕ использовать '\.', писать 'IMG_.*jpg')
# Переменные задаются из конкретной задачи вне Git:
#   MM3D=/path/to/micmac/bin/mm3d
#   RUN=/ascii/path/to/micmac-run-01   # свежий пустой каталог с копиями оригиналов
#   PAT='.*jpg'                        # шаблон нужных оригиналов в $RUN
#   MODEL='FraserBasic'                # или RadialStd для малых/плоских наборов; FishEyeBasic для истинного fisheye

cd "$RUN"

# 1. Поиск связующих точек (800..1500 px; для >25 фото предпочтительнее MulScale 400 1500)
"$MM3D" Tapioca All "$PAT" 800 ByP=2 @ExitOnBrkp @ExitOnWarn @ExitOnNan

# 2. Самокалибровка и внешняя ориентация (Out — уникальное имя при сравнении моделей)
"$MM3D" Tapas "$MODEL" "$PAT" Out=Rel @ExitOnBrkp @ExitOnWarn @ExitOnNan

# 3. Проверка Ori-Rel/Residus.xml, Ori-Rel/AutoCal_*.xml и экспорт разреженного облака с камерами
"$MM3D" AperiCloud "$PAT" Rel Out=AperiCloud_Rel.ply @ExitOnBrkp @ExitOnWarn @ExitOnNan

# 4. Опционально (только после осмотра AperiCloud и Residus!): плотное CPU-облако
#    QuickMac + ZoomF=4 — быстрый осмотр; MicMac + ZoomF=2 — детальнее на малом участке (10..30 фото)
"$MM3D" C3DC QuickMac "$PAT" Rel ZoomF=4 Out=C3DC_QuickMac.ply @ExitOnBrkp @ExitOnWarn @ExitOnNan
```

**Правило безопасного повтора:** если изменились входные фото или `Tapioca`, создать **новый** каталог `$RUN`. Если меняется только модель в `Tapas`, задать новое имя `Out=Rel_RadialStd` и новое имя PLY (`Out=AperiCloud_Rel_RadialStd.ply`).

## 4. Пример правильной интерпретации результата (по реальной пробе #31)

- **Вход:** 8 публичных JPEG `1296×972` (`DevlopImage/P1056139.jpg..P1056146.jpg`, `DC-GX9`, `14 мм`).
- **Наблюдаемые выходы:** все 4 команды завершились с `rc=0` за `156.2 с` на CPU (`<NbMaxProc> 2`). Ориентированы `8/8` кадров; в `Ori-Rel/Residus.xml` после 32 итераций `AverageResidual = 0.2908 px`, по кадрам `0.2759–0.2997 px`, `99.49–99.98%` inliers. В `AutoCal_Foc-14000_Cam-DCGX9.xml` получены `F = 1095.48 px`, `PP = (643.15, 478.81)`, `ModPhgrStd` без аномальных коэффициентов. Построены `AperiCloud_Rel.ply` (`44 723` вершины) и `C3DC_QuickMac.ply` (`135 890` вершин с нормалями, `0` NaN/Inf, габариты `33.24 × 12.61 × 11.62`).
- **Корректный вывод агента:**
  - Статус точности: **`INTERNAL_ONLY` (`scale = unknown`)**.
  - Что доказано: внутренний расчёт на CPU устойчив, модель `FraserBasic` хорошо согласуется с наблюдениями, плотный PLY валиден и готов к визуальному осмотру в `Open3D`/`CloudCompare`.
  - Чего **НЕ** доказано: нет физического масштаба (габарит `33.24` — условные единицы, не метры и не миллиметры), нет независимой проверки размеров и точности кромок. Для перехода к обмерам нужны подтверждённая масштабная база и независимые контрольные замеры.

## 5. Пример корректного отказа от неподходящего сценария

### Кейс A: смазанное видео помещения без достаточного параллакса (аналог #25)
- **Запрос:** «AliceVision собрал только 17/160 кадров с видео комнаты — давай прогоним те же кадры в MicMac с `FishEyeEqui`, чтобы всё сшилось».
- **Корректный отказ агента:** отказать в слепом переключении на MicMac. Объяснить: по исходникам видны смаз движения/слабое перекрытие/видео-EIS, а широкоугольный JPEG телефона уже ректифицирован (не fisheye). Смена движка и модели дисторсии не добавит отсутствующих наблюдений. **Правильное действие:** перейти на резкие оригинальные фото в одном фиксированном режиме (как подтвердил прогон #27: 77/77 камер в штатном `Standard`).

### Кейс B: обмер проёма с печатными `CCTag3` под CAD (#29/#30)
- **Запрос:** «Давай прогоним новую съёмку проёма с 4 метками `CCTag3` сразу в MicMac V1 или MMVII вместо AliceVision, чтобы получить точные миллиметры».
- **Корректный отказ агента:** оставить основной маршрут **`Meshroom/AliceVision Legacy + CCTag3`** из #29/#30. Объяснить: MicMac V1 не распознаёт `CCTag3` (пришлось бы вручную отмечать центры в GUI), а MMVII поддерживает только несовместимые семейства `CERN`/`IGN` и не имеет самостоятельного многовидового MVS уровня `C3DC`. MicMac V1 разумно подключать лишь вторым (контрольным) CPU-прогоном на тех же фото, если в основном прогоне обнаружатся признаки изгиба или ошибки калибровки.
